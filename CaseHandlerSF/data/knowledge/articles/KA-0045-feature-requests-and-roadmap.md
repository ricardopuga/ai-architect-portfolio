## Process for agents

1. **Check whether the feature already exists.** Many "requests" are features the customer hasn't found. Search the knowledge base first.
2. **Find the matching request** on the Product Feedback board (internal) and link the case to it. If there's none, create one with the customer's use case in their own words.
3. **Set expectations.** Don't promise dates. Say: "I've added your request to FR-xxx. Product reviews requests monthly, and you'll be emailed if its status changes."
4. Close the case as **Resolved – Feature request logged**. Feature requests are always **Low** priority unless a contract commitment is involved.

## Status of frequently requested features (October 2026)

| Request | Status | What to tell the customer |
|---|---|---|
| **More interface languages** (FR-077) | Partly available | The app is available in English, Spanish, Portuguese (BR), French, German, Japanese and Dutch. Italian and Polish are planned for the first half of 2027. Users choose under **Profile > Preferences > Language** |
| **More detailed report filters** (FR-102) | Available | Advanced filters (AND/OR groups, relative dates, "is any of", filtering on related fields) are in **Filter > Advanced**. Many customers haven't found it |
| **Duplicate templates** (FR-095) | Available | **Templates > ⋯ > Duplicate**. To copy a project, use **Project > ⋯ > Save as template** |
| **Advanced analytics / funnels / user behavior** (FR-131) | Add-on | The **Lumora Insights** add-on (Business+) provides cycle-time, throughput and funnel charts. Product usage tracking of a customer's own end users isn't planned |
| **Scheduled export to cloud storage** (FR-118) | Beta | See KA-0024 |
| **Dark mode** (FR-012) | Available | See KA-0046 |
| **Sharing projects across workspaces** (FR-140) | Enterprise | See KA-0047 |
